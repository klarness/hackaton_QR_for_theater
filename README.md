# Геймифицированный WebAR-квест (Студия театрального искусства)

**MVP для хакатона «Креаторы и кодеры»**
Команда: **WW Team (SixSeven)**

Интерактивный AR-квест, который запускается прямо в мобильном браузере (без скачивания приложения). Зритель сканирует QR-код у афиши, на экране оживает театральный персонаж, ведёт диалог и в финале даёт промокод на билет.

---

## 🧱 Архитектура (актуальная)

Проект построен на **`<model-viewer>` от Google** + ванильный JS. От подхода с image-tracking (MindAR / A-Frame) отказались сознательно — он давал нестабильный, дёрганый трекинг на больших постерах.

Теперь AR работает через **родной слой устройства**:
- **Android Chrome** → Google Scene Viewer (ARCore)
- **iOS Safari** → Apple Quick Look (ARKit, требует `.usdz`)

Внутри страницы (без AR-режима) персонаж рендерится как полноэкранная 3D-сцена, которую можно крутить пальцем.

**Что осталось из старой версии:**
- UI-оверлей (диалог, кнопки выбора, тосты)
- Стейт-машина прогресса на `localStorage`
- Dev-кнопки для имитации сканирования
- Финальный экран с промокодом и редиректом на сайт

## 🚀 Как запустить и протестировать на телефоне

Для камеры нативного AR обязателен **HTTPS** — `http://localhost` через туннель не подойдёт для AR-режима (для инлайн-3D подойдёт). Лучший вариант — деплой на Vercel/Netlify/GitHub Pages.

### Вариант A — Деплой (рекомендуется)

1. Запушить репозиторий на GitHub.
2. Подключить к Vercel (`vercel.com` → New Project → Import) или Netlify.
3. Деплой статический, никакой конфигурации не нужно — просто статика.
4. Получаешь `https://your-project.vercel.app` — открываешь на телефоне.

### Вариант B — Локальный сервер + туннель (для итераций)

Подходит для отладки UI и инлайн-3D, но AR-режим на iOS / Android через туннель может не сработать.

Терминал 1 — сервер:
```bash
npx serve -p 3000
```

Терминал 2 — HTTPS-туннель:
```bash
ssh -R 80:localhost:3000 nokey@localhost.run -o StrictHostKeyChecking=no
```
(альтернатива: `npx localtunnel --port 3000`)

Открой выданную `https://*.lhr.life` ссылку на телефоне.

### Что должно произойти на телефоне

1. Открывается интро-экран → жмёшь **«Начать»**.
2. Появляется 3D-персонаж (сейчас — куб-заглушка), которого можно крутить пальцем.
3. Снизу — реплика и кнопки выбора.
4. На Android появляется кнопка **«👁 Посмотреть в моём пространстве»** → тап → откроется Scene Viewer, персонажа можно поставить на пол и обойти.
5. На iOS та же кнопка появится, только если рядом с `.glb` лежит `.usdz` файл (см. раздел про iOS ниже).

### Dev-кнопки

Слева сверху есть `[Dev] marker1`, `[Dev] marker2`, `[Dev] Сброс` — для имитации сканирования разных QR без перезагрузки страницы.

## 🔗 Как работают QR-коды

Каждый QR ведёт на ту же страницу, но с параметром `?m=`:

| QR на афише        | URL                                       | Сцена         |
|--------------------|-------------------------------------------|---------------|
| Афиша «Чайка»      | `https://your-domain/?m=1`                | Чехов         |
| Афиша «Ревизор»    | `https://your-domain/?m=2`                | Мейерхольд    |

Соответствие задано в `app.js` в объекте `URL_TO_MARKER`. Чтобы добавить новый маркер — добавь сцену в `questData` и строку в `URL_TO_MARKER`.

Сгенерировать QR-коды с этими URL можно на `https://qr-code-generator.com` или подобном сервисе.

## 📋 Что нужно докрутить, чтобы было «всё по красоте»

Базовый каркас на кубе уже работает. Чтобы получить финальный продукт — нужно сделать следующее.

### 1. Заменить куб на 3D-персонажей

Сейчас и Чехов, и Мейерхольд используют `cube.glb`. В `app.js` в `questData` поле `modelUrl` нужно указать на свои `.glb`:

```js
modelUrl: "./chekhov.glb",   // для marker1
modelUrl: "./meyerhold.glb", // для marker2
```

**Где взять модели:**
- **Mixamo** (`mixamo.com`, бесплатно, нужен Adobe-аккаунт) — выбираешь персонажа, навешиваешь анимации `Idle` и `Talking`, скачиваешь FBX → конвертируешь в `.glb` через `https://fbx2gltf.com` или Blender.
- **Sketchfab** (`sketchfab.com`) — фильтр «Downloadable» + «Free» + формат glTF/glb. Искать `man character`, `gentleman`, `victorian man`.

**Требования:**
- Формат: `.glb` (бинарный glTF — один файл со всем внутри).
- Размер: до 5 МБ (иначе долго грузится с мобильного интернета).
- Внутри должны быть анимационные клипы с названиями `idle` и `talk` — код переключает их через `model-viewer`'s `animation-name`. Если клипы названы иначе — поправь вызовы `this.playAnimation('idle' / 'talk')` в `app.js`.

### 2. Поддержка AR на iOS (генерация `.usdz`)

`<model-viewer>` на iOS Safari запускает AR через Apple Quick Look, и Quick Look понимает **только** формат `.usdz`. Без него на айфоне AR-кнопка просто не появится — будет только инлайн-3D.

**Как сделать `.usdz`:**

Способ 1 — онлайн-конвертер:
- `https://products.aspose.app/3d/conversion/glb-to-usdz`
- Загружаешь `chekhov.glb` → получаешь `chekhov.usdz`.

Способ 2 — Reality Converter (Mac, лучше качество):
- Скачать у Apple (`developer.apple.com/augmented-reality/tools/`)
- Drag-and-drop `.glb` → Export as `.usdz`.

Положи `.usdz` рядом с `.glb` в корень проекта и добавь атрибут `ios-src` в `<model-viewer>` в `index.html`:

```html
<model-viewer
    id="ar-model"
    src="./cube.glb"
    ios-src="./cube.usdz"
    ...>
```

⚠️ Если модель меняется динамически (как у нас — разные персонажи для разных маркеров), `ios-src` тоже нужно менять. В `app.js` в методе `setModel(url)` дописать:
```js
this.ui.model.setAttribute('ios-src', url.replace('.glb', '.usdz'));
```
И убедиться, что для каждого `.glb` рядом лежит одноимённый `.usdz`.

### 3. Реальные аудио-реплики

Сейчас в `questData` поле `audioUrl` указывает на `/mock-audio-1.mp3`, и проигрывание закомментировано в `app.js` (метод `startScene`, строка с `new Audio(...)`).

**Шаги:**
1. Сгенерировать озвучку реплик через **ElevenLabs** (бесплатные минуты) или **Yandex SpeechKit**. Сохранить как `.mp3`.
2. Положить в папку `/audio/` (создать).
3. В `questData` указать пути: `audioUrl: "./audio/chekhov_greeting.mp3"`.
4. В `app.js` раскомментировать строку `new Audio(scene.audioUrl).play()`.

⚠️ **Важно для iOS:** автозапуск аудио в Safari заблокирован до первого тапа пользователя. У нас это нормально, потому что аудио стартует после нажатия «Начать».

### 4. Контент диалогов

Сейчас тексты — заглушка. В `questData` (`app.js`, строки 5–28) для каждого `marker` заполнить:
- `character` — имя персонажа
- `dialogue` — что он говорит при появлении
- `options` — варианты ответа пользователя и `nextAction` (`talk_next` / `explain_rules` / `show_promo`)

Дополнительные ветки диалога добавляются через `renderOptions(...)` внутри `handleOptionClick` (пример — ветка `explain_rules`).

### 5. Печать афиш и QR-кодов

- QR-коды для `?m=1`, `?m=2` сгенерировать → распечатать на афишах театра.
- На демо иметь минимум одну распечатанную афишу с QR, чтобы жюри могло отсканить.

### 6. (Опционально) Кастомизация AR-кнопки и UI

- Текст AR-кнопки задаётся в `index.html` внутри `<button slot="ar-button">`.
- Стилизация — в `style.css`, класс `.ar-button`.
- Цвета бренда — в `:root` (`--primary`, `--secondary`).

## 🛠 Стек

- **HTML5 / CSS3 / Vanilla JS** — никаких фреймворков, для максимальной стабильности и быстрой загрузки.
- **`<model-viewer>` от Google** (`@google/model-viewer@3.5.0`) — инлайн-3D + мост к нативному AR.
- **ARKit (iOS) / ARCore (Android)** — нативный AR-трекинг через системный API, без сторонних библиотек.
- **localStorage** — прогресс квеста.

**Что убрано:** A-Frame, MindAR, image-tracking, `.mind` файлы. Подход с трекингом картинки дал нестабильный результат на больших постерах и заменён на нативный AR.
